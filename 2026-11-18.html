Java4Shell: critical memory-corruption bug in OpenJDK's Base64 decoder allows remote code execution Calif · HN 938Rated 9.2 under CVSS 4.0, reachable without credentials, and found with AI in about an hour.

Calif disclosed CVE-2026-114938 in the hand-written AVX-512 assembly OpenJDK uses to speed up Base64 decoding on x86-64. A malformed input of 64 "A" characters and one "=" causes a 64-byte write that runs 62 bytes past the end of the buffer. The team says it demonstrated remote code execution against widely deployed Java applications in default configurations, and against sample Struts and Spring Boot apps; a client connecting to a malicious TLS server can also be hit. There is no universal exploit, since it depends on how each application uses Base64. Calif says one researcher found it in an hour and had a working exploit two hours later for under $200 in tokens. Anything you run on a JVM is worth a version check today.

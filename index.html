DeepSeek open-sources DeepInfer, the Apache-2.0 inference stack behind V4.1-Flash — deterministic batch-invariant serving, speculative decoding, and day-one parity on NVIDIA SM100 and Huawei Ascend 950 — while its own numbers imply ~$38 per GPU-hour and an 80%-plus inference margin GitHub · HN 2,242 pts · Latent Space The biggest HN thread of the year so far. The production crown jewels stay closed, but the published economics are the real story.

Released on day one of PyTorch Conf. DeepInfer is the framework DeepSeek actually serves V4.1-Flash with, offered as offline inference only: attention data-parallelism with MoE expert parallelism and EPLB, sliding-window bounded replay, a zero-overhead async batch scheduler, "DSpark" speculative decoding, batch-invariant deterministic outputs, and structured output via regex, JSON schema or EBNF. Explicitly held back are the pieces that make production cheap — the compact 8-hour-plus KV-cache manager, prefill/decode disaggregation and load balancing. DeepSeek credits vLLM as the base (vLLM's reply: its own decode throughput is within 6% on GB200). swyx's AINews does the arithmetic on the first-party claims: 155T tokens a day per cluster, 96% cache hits, 72-hour prompt caching against OpenAI's new 12 hours, which at $0.15/$0.60 per million tokens works out to roughly $38 per GPU-hour, about $22M a day, an inference margin above 80% and an 81-day payback — unaudited, but if even half right it sets the floor for what AI features in SaaS will cost to run, and how fast per-token pricing compresses.

Eight eMudhra intermediate CA certificates chaining to roots trusted by Mozilla, Microsoft, Apple and Chrome were generated with flawed keys that anyone can recover from the public certs — exploitable since April 2025 — and were blocked in Firefox and Chrome Oct 17, Apple Oct 19, Microsoft Oct 20 we-have-a-problem.com · HN 914 pts A publicly trusted CA shipped intermediates with recoverable private keys for 18 months. Browsers are fixed; anything that isn't a browser may not be.

The reporter proved possession by signing a message with all eight recovered keys; an attacker holding them could impersonate any website. No Certificate Transparency log entries exist for the window, so CT-enforcing browsers could not have been attacked — but non-browser clients that ignore revocation (IoT, embedded, curl builds without CRL support, older mobile apps) need a software update rather than a flag. The page provides test hosts and a chains.zip for checking your own trust store; the CA has revoked the certificates and the Sectigo cross-signs are listed. For the PuckFinder and Pulse stacks: Node and Python on current OS trust stores are fine; the thing to check is any pinned or vendored CA bundle.

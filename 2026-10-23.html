NVIDIA open-sources OpenShell (Apache-2.0, about 18k GitHub stars), a runtime for fleets of autonomous agents that enforces a per-agent policy at kernel level on every file access, system call and network connection, and formally verifies policy changes so risky new access waits for a human GitHub · HN 389 Agents never see the real credentials. The runtime adds them only to requests going to approved endpoints.

OpenShell keeps secrets out of the agent's context and adds them only to outbound requests bound for allow-listed endpoints, so a prompt-injected agent has no keys to leak. It enforces policy at the kernel level rather than in the prompt. A policy change that would widen access is checked formally and, if risky, held for human sign-off. Release 0.1.x brings a stable release cadence, new isolation primitives and new APIs. Given this week's supply-chain stories below, the "never hand the agent the key" design is the right default.

Microsoft's MAI-DxO — a panel of AI agents that question the patient, order tests and debate a diagnosis — gets 83% of complex NEJM cases right versus 36% for generalist physicians, in a Science paper Mustafa Suleyman calls a step toward "medical superintelligence" TechCrunch The headline number is real, but most of the gain comes from the underlying model, not the agent panel.

Specialists weren't in the comparison. GPT-5 alone with a basic prompt scored 78.9%, at about $8,400 in simulated test costs per case. The DxO panel added about four points of accuracy and cut the cost by roughly $3,000. It made little difference on emergency-department cases. For anyone building agents on top of a frontier model, the useful lesson is that orchestration mostly buys efficiency here, not much accuracy.

Innovation & Infra

Anthropic's Frontier Red Team and Theorem had Claude formally prove security properties, down to RISC-V assembly, for 123 open-source libraries — showing the fuzz-test binaries never crash or fail an assertion for any input under 64 MB — and found hundreds of bugs that trillions of fuzz runs had missed Anthropic · HN 342 For scale: verifying the seL4 kernel took 20 person-years against 2 to build it. This turns existing fuzz tests into proofs.

The method turns each library's existing fuzz harnesses into formal specs, then has Claude prove them, patching bugs as they turn up. Fuzzers would rarely hit the bugs it found: an out-of-bounds write in a decompressor triggered only by ~20 MB inputs, an image-decoder read needing a 64 MB input and 2 GB of RAM, and a rediscovery of libexpat CVE-2026-56132. Anthropic is publishing a subset of the proofs, and Theorem is releasing a Claude skill and offering to run the pipeline for other open-source maintainers. If the cost keeps falling, formal verification moves from seL4-scale projects to the ordinary libraries everything else depends on.

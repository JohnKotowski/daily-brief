Mesh LLM: pool GPUs across your machines for local inference iroh · HN 245 An OpenAI-compatible endpoint that routes inference locally, to a peer, or split across machines — 235B-parameter models on modest hardware.

Mesh LLM, built on the iroh peer-to-peer stack, pools GPUs and memory across multiple machines and exposes them through a single OpenAI-compatible API at localhost. Inference routes to wherever it runs best: locally, to a peer that already has the model loaded, or split across machines in pipeline stages — the "Skippy" split mode gets models up to 235B parameters running on hardware no single box could handle, with a catalog of 40+ models from laptop-sized to large mixture-of-experts. The interesting angle is what this does to the "you need a cloud contract for serious models" assumption: a small office full of ordinary workstations is quietly becoming a viable inference cluster.

ClickHouse scaled PgBouncer to 4x throughput ClickHouse · HN 206 One PgBouncer process maxed a single core at ~87k TPS while 15 cores idled — a process fleet with so_reuseport pushed it to ~336k.

ClickHouse's managed Postgres team hit PgBouncer's classic ceiling: it's single-threaded, so one process saturated a single core at ~87k transactions/second while the other 15 vCPUs sat idle. Their fix — a fleet of PgBouncer processes bound with so_reuseport so the kernel load-balances connections, plus peering between them — lifted throughput to ~336k TPS, about 4x. Nothing exotic, which is the point: the most-deployed Postgres connection pooler in the world leaves 4x on the table with default deployment, and the write-up is a copy-paste-able recipe for anyone running Postgres at scale.
